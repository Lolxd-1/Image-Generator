# T05 Report: storage usage, purge-images, delete-catalog

## Implemented
- `backend/app/storage.py`: added `delete_many(keys)` to the `Storage` Protocol and both
  `SupabaseStorage` (chunks at 100, one `remove()` call per batch in a worker thread via
  `anyio.to_thread.run_sync`, swallows a per-batch exception with a `logger.warning`) and
  `LocalStorage` (unlinks each existing path in a single worker-thread call).
- `backend/app/routers/storage.py` (new): pure helpers `StoredObject`, `summarise`,
  `purge_plan`, `delete_plan`, `BUDGET_BYTES`, exactly as specified in Contracts; `_collect`
  (3 queries, no N+1); a shared `_shop_storage_out` helper (kind->(count,bytes) ->
  `ShopStorageOut`, reference_bytes = reference + item_ref) reused by both GET routes;
  `_get_shop_or_404` and `_refuse_if_job_running` (409 `conflict` on a RUNNING job) shared by
  the two destructive routes.
  - `GET /storage`: all shops via 3 grouped queries (images GROUP BY shop_id, kind; one count
    query each for menu_uploads/exports) - no per-shop query.
  - `GET /shops/{id}/storage`: `summarise(_collect(...))` per Contracts.
  - `POST /shops/{id}/purge-images`: nulls `items.image_id` for affected items, deletes dish
    blobs, deletes `Image` rows, commits; item statuses untouched (commented why).
  - `DELETE /shops/{id}`: blobs first via `delete_plan(_collect(...))`, then nulls the four
    FKs + flush, then deletes `job_events, jobs, exports, images, items, menu_uploads`, then
    the shop row, in that exact order.
- `backend/app/main.py`: added `storage_router` to the mounting tuple.
- `backend/tests/test_storage_usage.py` (new): TC1-TC5 from the brief, pure functions only,
  no DB fixture.

## Discoveries
- `ShopStorageOut` (from T01's schemas.py) has no `reference_count` field - only
  `reference_bytes`. Any future UI work (T07) showing per-kind counts should be aware
  reference/item_ref images are counted in `dish_count`+`menu_count`+`export_count`'s sibling
  total but have no dedicated count field.
- The full route bodies for `purge-images` and `DELETE /shops/{id}` are not exercised by the
  test suite (per the brief: "the suite has no DB fixture" for this file) - only their
  existence is checked via route introspection in Verify. Behavioral correctness of the DB
  work rests on this report's manual trace against the brief's exact Steps, not on an
  automated integration test.
