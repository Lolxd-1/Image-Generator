# T03: key-pool API (/api/auth/keys), pool-aware /me, boot-time backfill

## Implemented
- `backend/app/routers/keys.py` (new): `router = APIRouter(prefix="/auth/keys", ...)` with
  - `_validate_live(key)`: live Gemini ping, extracted verbatim from the old
    `put_gemini_key`, raising `auth_failure`/`rate_limited`/`validation_failed` exactly as
    before. Never echoes the raw exception text.
  - `_key_out(db, key)`: fills `delay_s`/`next_allowed_at`/`busy` from the key's `PaceState`
    row (missing row -> `pacer.RATE_START_DELAY`, `None`, `False`).
  - `_get_key_or_404`: shared 404 helper (missing or not the caller's key).
  - `GET  /auth/keys` -> caller's keys ordered by `created_at`.
  - `POST /auth/keys` -> strips key, 400 `validation_failed` on empty, runs `_validate_live`
    in a worker thread (`anyio.to_thread.run_sync`), computes the `Key {n+1}` default label
    only when `payload.label is None`, calls `keypool.add_key` (409 `conflict` on duplicate
    passes through), 201 with `_key_out`.
  - `PATCH /auth/keys/{key_id}` -> 404 if missing/not caller's; applies only set fields;
    re-enabling clears `disabled_reason` and the key's `PaceState.leased_until`; disabling
    touches neither.
  - `DELETE /auth/keys/{key_id}` -> 404 or `keypool.delete_key` + 204.
  - `POST /auth/keys/{key_id}/test` -> 404, decrypt, `_validate_live` in a worker thread; on
    `auth_failure` calls `keypool.disable` then re-raises; `rate_limited`/other re-raise
    unchanged without disabling; on success sets `enabled=True`, clears `disabled_reason`.
- `backend/app/routers/auth.py`:
  - `_me_out` is now `async def _me_out(db, user)`, deriving `key_count`, `enabled_key_count`,
    `has_gemini_key` (`enabled_key_count > 0`), and `gemini_key_hint` (oldest enabled key's
    hint, else `None`) from the `api_keys` table instead of `users.gemini_key_enc`. `GET /me`
    awaits it.
  - `put_gemini_key` now delegates: `_validate_live` (imported from `app.routers.keys`) in a
    worker thread, then `keypool.add_key(db, user.id, key, "Primary")`; a 409 `conflict` is
    swallowed as success and the existing pool row's hint is looked up and returned.
  - `delete_gemini_key` now deletes every row in the caller's pool via `keypool.delete_key`
    per row, then clears `user.gemini_key_enc`/`gemini_key_hint` so boot backfill can't
    resurrect them.
  - Removed now-unused imports (`crypto`, `gemini.build_client`/`VISION_MODEL`/
    `is_auth_error`/`is_rate_limit`); added `anyio`, `func`, `keypool`, `gemini.key_hash as
    gemini_key_hash`, `ApiKey`, and the `_validate_live` import from `app.routers.keys`.
- `backend/app/main.py`:
  - Imports and mounts `keys_router` alongside the others in the single mounting loop.
  - `lifespan` calls `await keypool.migrate_legacy_keys(session)` right after `seed_users`,
    inside the same session block, wrapped in try/except that logs a warning and continues.
