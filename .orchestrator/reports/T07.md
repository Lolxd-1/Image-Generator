# T07: Settings screen (keys + storage) and the download / delete controls

## What was implemented
- `frontend/src/screens/settings/KeyPoolSection.tsx` (new): paste box (`Input type="password"
  autoComplete="off"` + optional label + Add key), summary line "N keys · M enabled · up to L
  parallel lanes" (`L = min(max(M,1),6)`), explain line about lanes capped at 6. MULTI-PASTE:
  splits pasted text on `/[\n,]+/`, trims, drops empties; a single result adds normally (clears
  field, toast "Key added"), more than one adds sequentially (`for...await`, one
  `useAddApiKey().mutateAsync` at a time) and reports "Added X of Y keys" plus a failure list
  (masked key preview + reason) for any that failed. Row list: inline-editable label (its own
  `useUpdateApiKey` call), `key_hint`, enabled/disabled `Badge`, "Busy" badge, `last_used_at` as
  a local `relativeTime()` string, `Math.round(delay_s)`s pace, "Available in Ns" from
  `next_allowed_at` (ticked once/second only while some key is busy or pending, via one
  `setInterval` in the parent). Row actions: Test/Enable-Disable/Delete, Delete behind
  `window.confirm`. `disabled_reason` shown in `text-danger-400` when the key is disabled.
  `keyErrorMessage()` maps `conflict`/`auth_failure`/`rate_limited` to the brief's exact copy,
  else falls back to `err.message`. Zero keys renders `EmptyState` instead of the row list (the
  paste form still renders above it).
- `frontend/src/screens/settings/StorageSection.tsx` (new): `formatBytes` (exported, per the
  contract) — "0 B" for `<= 0`, integer B/KB/MB, one-decimal GB. `useStorageUsage()` drives a
  usage bar (`bg-accent-600` under 75%, `bg-warn-500` 75-90%, `bg-danger-500` above 90%) and a
  shop list sorted by `total_bytes` descending, each row showing total + dish count + a
  dish/menu/reference/export byte breakdown, with "Download images" (`<a href={shopImagesZipUrl(id)}>`
  wrapping a `Button` — a plain link, matching the existing `CatalogCard` download-link
  pattern), "Free up space" (`usePurgeShopImages`, `window.confirm`, toast "Freed <bytes>" on
  success), and "Delete catalog" (`Modal` requiring the shop name typed exactly, trimmed, to
  enable the danger button; `useDeleteShop` already invalidates `qk.shops`/`qk.storage` in
  `api/hooks.ts` so no manual invalidation was added here).
- `frontend/src/screens/Settings.tsx` (new): page shell matching `Shops.tsx`
  (`mx-auto max-w-5xl px-6 py-8`), `h1` "Settings", back link to `/`, then the two sections.
- `frontend/src/router.tsx`: added `<Route path="/settings" element={<Settings />} />` inside
  `RequireAuth`.
- `frontend/src/screens/Shops.tsx`: header gained a "Settings" link (secondary button) next to
  "New shop". Each `ShopCard` gained a danger-styled "Delete" button (kept "Archive" as-is,
  still reversible via `window.confirm`); a new `DeleteShopModal` (same type-the-name pattern
  as `StorageSection`'s, duplicated here per the brief's write-set — no new shared file was in
  scope) gates the actual `useDeleteShop` call.
- `frontend/src/screens/Catalog.tsx`: header now also shows "Download all images"
  (`shopImagesZipUrl` link) and "Free up space" (`usePurgeShopImages`, confirm-gated, toast on
  success), plus a "· <bytes> stored" suffix on the existing summary line from
  `useShopStorage(shopId)`.
- `frontend/src/screens/catalog/CatalogCard.tsx`: the `<img>` is now conditional on
  `item.image_id` — null renders a neutral "Image removed to free space" placeholder div of the
  same size instead of a broken image. Only that one branch changed; everything else (edit
  form, download link, regenerate modal) is untouched.
- `frontend/src/screens/Generate.tsx`: added `useApiKeys()`, computed
  `lanes = min(max(enabledKeys.length, 1), 6)`, passed it to `useGenerateLoop(jobId, lanes)`;
  ETA is now divided by `lanes` (`(waitMs * remaining) / 1000 / lanes`); added a
  "N lanes running on M keys" line above `ProgressPanel`. `ProgressPanel`'s own props are
  unchanged — `lanes` is folded into `eta` before it's passed down.

## Tests / verification
No frontend test runner exists (confirmed by the brief); each Test case is a code-path
assertion satisfied by the diff:
- TC1: a single pasted key takes the `parts.length === 1` branch — one `addKey.mutateAsync`
  call, `pasteText`/`label` cleared on success.
- TC2: `parts.length > 1` takes the sequential `for...await` branch and sets
  `multiResult = { added, total, failures }`, rendered as "Added X of Y keys."
- TC3: `keyErrorMessage()` maps `ApiError.code === "conflict"` to "That key is already in the
  pool."; on failure only `setFormError`/`failures` change, no query invalidation runs, so the
  list is unchanged.
- TC4: `keys.length === 0` renders `EmptyState` (title "No keys yet", description telling the
  operator to paste a key above); `StorageSection` is an independent sibling component and
  always renders regardless of key count.
- TC5: both delete-catalog modals disable the danger `Button` via
  `disabled={typed.trim() !== name}` (case-sensitive, trimmed).
- TC6: "Download images"/"Download all images" are `<a href=...>` wrapping a `Button` for
  style only — no `fetch`/`onClick` handler, so the browser streams the attachment directly.
- TC7: `CatalogCard` renders the placeholder div whenever `item.image_id` is null; `Catalog.tsx`
  only ever passes items with `status` in `{generated, hosted}` to `CatalogCard` (existing
  `SHOWN_STATUSES` filter), so the placeholder only appears for that status pair per the brief.

- "Divide the existing ETA by the lane count" and "N lanes running on M keys" both use the
  enabled-key-derived `lanes` value (matching the exact expression the brief gives for the
