# T02 Report: app/engine/keypool.py - lease, release, disable and pick a key from the pool

## What I implemented
- `backend/app/engine/keypool.py` (new): the module that owns every decision
  about WHICH Gemini key a request uses.
  - Constants `LEASE_SECONDS = 150`, `MAX_LANES = 6`, `WAIT_CAP_MS = 60_000`.
  - `Candidate` frozen dataclass; `free_at` (later of `next_allowed_at` /
    `leased_until`, naive datetimes coerced to UTC via `_aware`);
    `wait_ms_until` (drops disabled, `None` if none enabled, `0` if any free,
    else soonest wait clamped to `[1, WAIT_CAP_MS]`); `lane_count`
    (`min(max(enabled, 1), MAX_LANES)`).
  - `lease`: single `UPDATE pace_state ... WHERE api_key_hash = (SELECT ...
    FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING api_key_hash`, copied from the
    brief's exact statement shape (mirrors the item-claim in
    `stepper.py:240-270`); then loads the matching `ApiKey`, stamps
    `last_used_at`, commits once (so the lease is visible to concurrent
    callers before the caller makes its API call), returns
    `(ApiKey, plaintext)` or `None`.
  - `release` / `release_now`: plain `UPDATE pace_state` by hash, no-op-safe
    when no row exists (an `UPDATE` matching zero rows raises nothing).
  - `wait_ms`: outer-joins `api_keys` to `pace_state` for the user so a key
    with no pace row still counts as free, builds `Candidate`s, delegates to
    `wait_ms_until`.
  - `enabled_count`, `disable` (flips every `api_keys` row sharing the hash,
    truncates `disabled_reason` to 300 chars, clears `leased_until`),
    `add_key` (409 `AppError("conflict", ...)` on duplicate `(user_id, hash)`,
    else encrypts/hints/inserts + `pacer.get_or_create`), `delete_key`
    (deletes the `ApiKey` row, then the `pace_state` row only if no other
    `api_keys` row still shares that hash), `pick_any` (oldest
    `last_used_at` first, no lease taken, 400 `AppError("no_api_key", ...)`
    when the user has no enabled key), `migrate_legacy_keys` (per legacy
    `users.gemini_key_enc`, decrypt-and-insert if not already present;
    `except Exception` around decrypt logs only `user.id` via the module
    logger and skips — never logs ciphertext/plaintext).
  - Imported `gemini.key_hash` as `gemini_key_hash` to avoid shadowing by the
    `key_hash` parameter name used in `release`, `release_now`, and `disable`.
- `backend/tests/test_keypool.py` (new): 9 pure-function tests over
  `Candidate`, no DB/network, following `test_pacer.py`'s style.
  - `test_wait_ms_until_free_key_returns_zero` (TC1)
  - `test_wait_ms_until_picks_soonest` (TC2, asserts within 100ms of 10_000)
  - `test_wait_ms_until_ignores_disabled` (TC3)
  - `test_expired_lease_counts_as_free` (TC4)
  - `test_wait_ms_until_no_enabled_candidates_returns_none` (TC5, empty +
    all-disabled)
  - `test_wait_ms_until_caps_at_wait_cap` (TC6)
  - `test_lane_count_caps_at_max` (TC7)
  - `test_free_at_prefers_later_constraint` (TC8)
  - `test_wait_ms_until_accepts_naive_datetimes` (TC9)
