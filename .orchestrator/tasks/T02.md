# T02: app/engine/keypool.py - lease, release, disable and pick a key from the pool
Wave: 2 · Deps: T01 · Risk: high · Model: sonnet

## Goal
A single module owns every decision about WHICH Gemini key a request uses, leasing it
atomically so two concurrent `/step` calls can never receive the same key, and releasing it
with the pace delay that key has earned.

## Context
T01 added the `api_keys` table and `pace_state.leased_until`. This module is the only place
that reads or writes those two tables together. `app/engine/pacer.py` already owns the
grow/shrink/backoff maths per key hash and is used unchanged: keypool decides WHICH key,
pacer decides HOW LONG that key waits.

## Contracts
- Consumes: `pacer.get_or_create(db, api_key_hash) -> PaceState`,
  `gemini.key_hash(plain) -> str`, `crypto.encrypt/decrypt/key_hint`.
- Produces (exact signatures - later tasks are written against these):
```python
LEASE_SECONDS = 150        # must exceed gemini.API_TIMEOUT (90s) plus storage-write headroom
MAX_LANES = 6
WAIT_CAP_MS = 60_000

@dataclass(frozen=True)
class Candidate:
    key_hash: str
    enabled: bool
    next_allowed_at: datetime | None
    leased_until: datetime | None
    last_used_at: datetime | None

def free_at(c: Candidate) -> datetime | None
def wait_ms_until(cands: Sequence[Candidate], now: datetime) -> int | None
def lane_count(enabled: int) -> int

async def lease(db: AsyncSession, user_id: uuid.UUID) -> tuple[ApiKey, str] | None
async def release(db: AsyncSession, key_hash: str, delay_s: float) -> None
async def release_now(db: AsyncSession, key_hash: str) -> None
async def wait_ms(db: AsyncSession, user_id: uuid.UUID) -> int | None
async def enabled_count(db: AsyncSession, user_id: uuid.UUID) -> int
async def disable(db: AsyncSession, key_hash: str, reason: str) -> None
async def add_key(db: AsyncSession, user_id: uuid.UUID, plain: str, label: str) -> ApiKey
async def delete_key(db: AsyncSession, key: ApiKey) -> None
async def pick_any(db: AsyncSession, user_id: uuid.UUID) -> str
async def migrate_legacy_keys(db: AsyncSession) -> int
```

## Steps
1. Module docstring: this module owns key selection; pacer owns pace maths; the plaintext a
   function returns must never be logged, persisted or put in a response.
2. `free_at(c)`: the later of `next_allowed_at` and `leased_until`, treating `None` as "no
   constraint". Both `None` -> `None` (free now). Compare timezone-aware datetimes only;
   if a value arrives naive, treat it as UTC (`.replace(tzinfo=timezone.utc)`) rather than
   raising - asyncpg can return naive values through some drivers.
3. `wait_ms_until(cands, now)`:
   - drop every candidate with `enabled is False`
   - no candidates left -> return `None` (caller decides: there is no usable key at all)
   - any candidate whose `free_at` is `None` or `<= now` -> return `0`
   - otherwise `min(free_at) - now` in whole ms, at least 1, capped at `WAIT_CAP_MS`
4. `lane_count(enabled)`: `min(max(enabled, 1), MAX_LANES)`.
5. `lease(db, user_id)`: ONE statement, modelled on the item claim in stepper.py:
   ```python
   now = datetime.now(timezone.utc)
   candidate = (
       select(PaceState.api_key_hash)
       .join(ApiKey, ApiKey.key_hash == PaceState.api_key_hash)
       .where(
           ApiKey.user_id == user_id,
           ApiKey.enabled.is_(True),
           or_(PaceState.next_allowed_at.is_(None), PaceState.next_allowed_at <= now),
           or_(PaceState.leased_until.is_(None), PaceState.leased_until <= now),
       )
       .order_by(PaceState.next_allowed_at.asc().nullsfirst(), ApiKey.last_used_at.asc().nullsfirst())
       .with_for_update(skip_locked=True, of=PaceState)
       .limit(1)
   )
   stmt = (
       update(PaceState)
       .where(PaceState.api_key_hash == candidate.scalar_subquery())
       .values(leased_until=now + timedelta(seconds=LEASE_SECONDS))
       .returning(PaceState.api_key_hash)
       .execution_options(synchronize_session=False)
   )
   ```
   Then load the `ApiKey` row for that hash and this `user_id`, set `last_used_at = now`,
   `await db.commit()`, and return `(key_row, crypto.decrypt(key_row.key_enc))`.
   Return `None` when the statement matched nothing.
   The lease MUST be committed before the caller makes its API call, otherwise a concurrent
   request cannot see it.
6. `release(db, key_hash, delay_s)`: `UPDATE pace_state SET next_allowed_at = now + delay_s,
   leased_until = NULL WHERE api_key_hash = :h`, then commit.
   `release_now`: same but only `leased_until = NULL`; leaves `next_allowed_at` alone.
   Both must be safe to call for a hash with no pace row (no-op, no exception).
7. `wait_ms(db, user_id)`: select the user's keys joined to their pace rows, build
   `Candidate`s (a key with no pace row is a candidate with all-`None` times), and return
   `wait_ms_until(...)`. Use an outer join so a key whose pace row is missing still counts
   as free.
8. `enabled_count(db, user_id)`: `SELECT count(*) FROM api_keys WHERE user_id = :u AND enabled`.
9. `disable(db, key_hash, reason)`: set `enabled = False`, `disabled_reason = reason[:300]`
   on every `api_keys` row with that hash, and clear that hash's `leased_until`. Commit.
10. `add_key(db, user_id, plain, label)`: compute `h = gemini.key_hash(plain)`; if a row with
    `(user_id, h)` exists raise `AppError("conflict", "That key is already in the pool.", status=409)`;
    otherwise insert the `ApiKey` (encrypted, hinted) AND ensure its pace row exists via
    `pacer.get_or_create(db, h)`; commit; return the row.
11. `delete_key(db, key)`: delete the `ApiKey` row; then delete its `pace_state` row ONLY if
    no other `api_keys` row shares that `key_hash` (two users may hold the same key). Commit.
12. `pick_any(db, user_id)`: the enabled key with the oldest `last_used_at` (nulls first);
    stamp `last_used_at = now`; commit; return the decrypted plaintext. No lease is taken -
    this serves the single-request jobs (extract, classify, reference analysis) which are not
    paced. Raise `AppError("no_api_key", "No Gemini API key is on file. Add one in Settings.", status=400)`
    when the user has no enabled key.
13. `migrate_legacy_keys(db)`: for every `users` row with a non-null `gemini_key_enc`,
    decrypt it, and if `(user_id, key_hash)` is not already in `api_keys`, insert it with
    `label="Primary"` plus its pace row. Return how many were inserted. Must be safe to run
    on every boot and must never raise on a key that fails to decrypt (log and skip - use a
    module logger, and never log the ciphertext or plaintext).

## Test cases
All tests are pure-function tests over `Candidate` - no database, no network (the existing
suite has no DB fixture; do not add one).
- TC1 (happy) `test_wait_ms_until_free_key_returns_zero`: three enabled candidates, one with
  `next_allowed_at=None` -> `0`.
- TC2 (happy) `test_wait_ms_until_picks_soonest`: candidates free in 30s, 10s and 90s ->
  a value within 100ms of 10_000.
- TC3 (edge) `test_wait_ms_until_ignores_disabled`: the only free candidate is
  `enabled=False` -> the answer comes from the enabled ones, not `0`.
- TC4 (edge) `test_expired_lease_counts_as_free`: `leased_until` 5 minutes in the PAST and
  `next_allowed_at=None` -> `0`.
- TC5 (error) `test_wait_ms_until_no_enabled_candidates_returns_none`: empty list -> `None`;
  all-disabled list -> `None`.
- TC6 (edge) `test_wait_ms_until_caps_at_wait_cap`: a candidate free in 10 minutes ->
  exactly `WAIT_CAP_MS`.
- TC7 (edge) `test_lane_count_caps_at_max`: `lane_count(0) == 1`, `lane_count(1) == 1`,
  `lane_count(5) == 5`, `lane_count(9) == 6`.
- TC8 (edge) `test_free_at_prefers_later_constraint`: `next_allowed_at` earlier than
  `leased_until` -> `free_at` returns `leased_until`, and vice versa; both `None` -> `None`.
- TC9 (edge) `test_wait_ms_until_accepts_naive_datetimes`: a candidate whose
  `next_allowed_at` is naive UTC does not raise and is treated as UTC.

## Notes
- `ORDER BY ... NULLS FIRST` in SQLAlchemy 2.0 is `col.asc().nullsfirst()`.
- `with_for_update(skip_locked=True, of=PaceState)` is required because the subquery joins
  `api_keys`; without `of=` Postgres tries to lock the joined table too and errors.
- The lease must be committed inside `lease()`; the caller's later `commit()` is for its own
  work and may be rolled back by an error path.
