# T04: route every Gemini call through the key pool (the parallel generate loop)
Wave: 4 · Deps: T02 · Risk: high · Model: sonnet

## Goal
`generate_step` leases one key from the pool per call, so K concurrent `/step` requests run
on K different keys; a 429 slows only the key that hit it; a bad key is disabled without
killing the run; and no item is ever claimed while the pool is busy.

## Context
T02 added `app/engine/keypool.py`. Today `generate_step(db, job, shop, api_key)` receives one
decrypted key from `routers/jobs.py` and gates on that key's `PaceState.next_allowed_at`.
That pace gate is replaced by a lease. The six step statuses SPEC.md pins down do not change;
three additive response fields do (`next_step_ms`, `key_hint`, `lanes`, added in T01).

## Contracts
- Produces:
```python
async def generate_step(db: AsyncSession, job: Job, shop: Shop, user: User) -> dict[str, Any]
# NOTE the signature change: `api_key: str` becomes `user: User`. Key selection now happens
# inside, because only the pool knows which key is free.
```
- Every `return` dict gains three keys, on every path including the early ones:
  `next_step_ms: int`, `key_hint: str | None`, `lanes: int`.
- `run_extract`, `run_classify` keep their `api_key: str` parameter; their callers now get
  that string from `keypool.pick_any(db, user.id)` instead of `decrypt(user.gemini_key_enc)`.

## Steps
1. `stepper.py`: add `from app.engine import keypool` to the existing engine import line.
2. Change `generate_step`'s signature to take `user: User` and update its docstring: say that
   the pace gate is now a per-key lease, that `next_step_ms` is the per-LANE wait while
   `next_delay_ms` stays the per-KEY pace, and that an auth failure disables one key rather
   than the job while other keys remain.
3. Add one local helper inside `stepper.py` so no return path can forget the new fields:
   ```python
   def _step_result(status, *, item=None, next_delay_ms=None, retry_after_ms=None,
                    next_step_ms=0, key_hint=None, lanes=1, job) -> dict[str, Any]
   ```
   which builds the full dict including `remaining`/`done`/`failed` from `job`. Rewrite every
   existing `return {...}` in `generate_step` to go through it. Keep the existing values for
   `status`, `item`, `next_delay_ms` and `retry_after_ms` exactly as they are today.
4. Replace the whole "Step 2 (pace gate)" block with the lease:
   ```python
   lanes = keypool.lane_count(await keypool.enabled_count(db, user.id))
   leased = await keypool.lease(db, user.id)
   if leased is None:
       w = await keypool.wait_ms(db, user.id)
       if w is None:            # no enabled key at all -> the job cannot continue
           job.status = JobStatus.FAILED
           job.error = "No enabled Gemini API key. Add one in Settings."
           job.finished_at = datetime.now(timezone.utc)
           await db.commit()
           await log(db, job, "error", job.error)
           return _step_result("failed", job=job, lanes=lanes)
       wait = max(w, 250)
       return _step_result("waiting", retry_after_ms=wait, next_step_ms=wait, job=job, lanes=lanes)
   key_row, api_key = leased
   key_hash, key_hint = key_row.key_hash, key_row.key_hint
   ```
   `job.api_key_hash` keeps recording the LAST key used (informational only) - set it to
   `key_hash` here.
5. Wrap everything from the item claim onwards so the lease is always given back. The simplest
   correct shape: a `try/except` around the body that calls `await keypool.release_now(db, key_hash)`
   before re-raising, plus an explicit release on every early return. Specifically:
   - no item claimed (the `item is None` branch, all three of its sub-branches - recovered /
     inflight / complete): `await keypool.release_now(db, key_hash)` FIRST, then the existing
     logic unchanged.
   - the "no reference image configured" per-item failure: `release_now`, then return
     `item_failed` with `next_step_ms=0`.
6. Outcome handling after `generate.generate_one`:
   - `RateLimited`: item back to QUEUED; `wait_s = await pacer.on_rate_limit(db, key_hash)`;
     `await keypool.release(db, key_hash, wait_s)`; then
     `w = await keypool.wait_ms(db, user.id)` and
     `wait = max(w if w is not None else int(wait_s * 1000), 250)`;
     return `rate_limited` with `retry_after_ms=wait, next_step_ms=wait`. The lane therefore
     waits only until ANOTHER key frees, not for the 429'd key.
   - `AuthFailure`: item back to QUEUED; `await keypool.disable(db, key_hash, str(e)[:300])`;
     `await log(db, job, "error", f"API key {key_hint} disabled: {e}", item.id)` - the hint,
     never the key; then `remaining_keys = await keypool.enabled_count(db, user.id)`:
     - `0` -> the existing whole-job failure path unchanged (`job.status = FAILED`, return
       `failed`).
     - otherwise -> return `waiting` with `retry_after_ms=250, next_step_ms=250` and
       `lanes=keypool.lane_count(remaining_keys)`. The run continues on the other keys.
   - `NoImage`: unchanged attempts/fallback-ladder logic; add
     `await keypool.release(db, key_hash, pace_delay)` where `pace_delay` is that key's
     current `delay_s` (read it from `await pacer.get_or_create(db, key_hash)`); return
     `item_failed` with `next_step_ms=0`.
   - success: unchanged storing logic; `next_delay_s = await pacer.on_success(db, key_hash)`;
     `await keypool.release(db, key_hash, next_delay_s)`; return `generated` with
     `next_delay_ms=int(next_delay_s * 1000)` and `next_step_ms=0`.
7. The bottom `except Exception:` safety net keeps putting the item back to QUEUED and adds
   `await keypool.release_now(db, key_hash)` before re-raising.
8. `routers/jobs.py`:
   - `step_job`: drop the `decrypt(user.gemini_key_enc)` block and call
     `await stepper.generate_step(db, job, shop, user)`. The `no_api_key` check moves into
     the pool (the "no enabled key" branch above), so remove it here.
   - `create_job`: for `EXTRACT`/`CLASSIFY`, replace the
     `if not user.gemini_key_enc: raise ...` + `decrypt(...)` pair with
     `api_key = await keypool.pick_any(db, user.id)` (it raises `no_api_key` itself).
   - Remove the now-unused `decrypt` import if nothing else in the file uses it.
9. `routers/shops.py`: `upload_reference` uses `api_key = await keypool.pick_any(db, user)` -
   pass `user.id` - instead of `require_gemini_key(user)`. Remove that import if unused.

## Test cases
- TC1 (happy): with 3 enabled free keys, three sequential `generate_step` calls lease three
  DIFFERENT hashes (each call leaves `leased_until` set until it releases). Demonstrate by
  reading the code path: `lease` only matches rows whose `leased_until` is null or past.
- TC2 (edge, R3): `lease` returns `None` -> the function returns `waiting` WITHOUT executing
  the claim statement, so no item can be left at `generating`.
- TC3 (error, AC3): `AuthFailure` with 2 other enabled keys -> status `waiting`, job still
  RUNNING, the failing key `enabled=False`; with 0 others -> status `failed`.
- TC4 (edge): `RateLimited` -> only that key's `next_allowed_at` moves; the returned
  `retry_after_ms` is the pool-wide wait, not that key's backoff.
- TC5 (error, R8): no decrypted key reaches a log line, a `JobEvent`, or a response field -
  only `key_hint`.
- TC6 (happy): every `return` from `generate_step` carries `next_step_ms`, `key_hint` and
  `lanes` (enforced by `_step_result`).

## Notes
- `job.api_key_hash` is informational; with a pool it simply records the last key used.
- Releasing twice is harmless (`release_now` on a cleared lease is a no-op), so prefer an
  extra release over a missed one.
- Do not add a new step status: the frontend union type is fixed by SPEC.md and T06 depends
  on exactly those six values.
