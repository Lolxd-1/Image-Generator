# T01: api_keys table, pace_state.leased_until, and the new response schemas
Wave: 1 · Deps: none · Risk: med · Model: sonnet

## Goal
The database can hold a pool of Gemini API keys per user and can record that one of them is
currently leased to an in-flight request; the Pydantic layer can describe keys, storage usage
and the two new step fields. No behaviour changes yet - this task is data shapes only.

## Context
Today a user has exactly one Gemini key (`users.gemini_key_enc`) and `pace_state` holds one
pace row per key hash. We are moving to N keys with server-side leasing so N `/step` calls
can run concurrently, one per key. Every later task builds on the names frozen here.

## Steps
1. `models.py`: add the `ApiKey` class after `User` (it references `users.id`). Import
   `UniqueConstraint` - already imported at the top of the file, confirm before adding.
2. `models.py`: add `leased_until` to `PaceState`, directly after `next_allowed_at`, with a
   one-line comment saying it is the concurrency lease held by an in-flight `/step` call.
3. `db.py`: inside `init_models()`, after `Base.metadata.create_all`, run the idempotent
   column migration in its own `engine.begin()` block:
   `ALTER TABLE pace_state ADD COLUMN IF NOT EXISTS leased_until TIMESTAMPTZ`
   wrapped in `try/except Exception` that logs a warning via a module `logging.getLogger(__name__)`
   and continues. `create_all` never adds a column to a table that already exists, and a
   deployed instance already has `pace_state`; a hard failure here would take the app down at
   boot on a database we cannot migrate, which is worse than running without the column.
   Use `sqlalchemy.text(...)` for the statement.
4. `schemas.py`: add the models above. Put the key models under the existing
   `# --- auth ---` section, and add a new `# --- storage ---` section before `# --- export ---`
   (or at the end if no export section exists). Every `*Out` model that is built from an ORM
   row gets `model_config = ConfigDict(from_attributes=True)`.
5. `schemas.py`: add the additive fields to `MeOut` and `StepResult`. Do not reorder or
   remove any existing field; defaults must make the new fields optional for existing callers.
